All detection results in the paper are obtained from simulation. Due to a data migration disaster the original code was lost. Due to this and other reasons you won't be able to get the results from the paper. The provided code is an attempt to get the results. You can get FPR ranging from 0.7% to 3.0% and detection rate ranging from 90% to 100% with this code. Same applies to all other figures where you may not able to achieve the same result but the trend is similar (e.g. ~20% UEs detected by on-path detector directly instead of ~30%, not reaching 100% detection rate as off-path mirroring limit increase, etc.). Close enough for me. You can probably get slightly better result if you want to spend months on it. You can tweak all those the training parameters, ccTLDs and threshold search parameters, some combinations/runs will give better result than others. Good luck.
The DNS based detection performance of Table 3 and 4 of Section 8.2 was NOT achieved with nested cross validation, instead similar performance can be achieved in one of the 2 ways: a) the detection performance was reported on a single 20% split testset while the rest 80% was used for training and threshold search, as was done in some of the previous works. b) 80%-20% cross validation was used where the valset was used for both threshold search and report of detection performance, the threshold search targets precision close to 95%. namely abs(p-0.95)<0.01. Also you need some luck.
The "same setting" in Appendix C ONLY refers to the direct use the dataset not the mixed one. Maybe some of the training hyper parameters are the same, that's all.
